# boss-greeter

BOSS 直聘自动打招呼。规则筛岗 → AI 判定外包/销售 → 大模型读 JD + 简历写针对性开场白 → 自动发送去重。

**不是 LLM 驱动的浏览器 agent**，而是确定性流水线 + LLM 只做两件擅长的事：判断岗位性质、写招呼语。
点哪个按钮、翻哪一页这类事全是规则，让模型去决策既慢又贵还不稳。

> ⚠️ 自动化操作违反 BOSS 用户协议，触发风控的后果是**你的账号被限制沟通**。
> 本项目仅供学习交流，用它之前请先读完[账号安全](#账号安全)一节。

## 它解决什么

手动刷 BOSS 的三件苦差事：

1. **搜索结果很散** —— 搜「Golang 架构师」会返回游戏开发、存储中间件、外包驻场、
   甚至 AI 产品经理。一半以上的卡片点开就该关掉。
2. **外包岗看不出来** —— 标题写着「Go 后端研发工程师」，点进去公司介绍才是
   「三大外包事业群，十六大城市外包事业部」。
3. **通用招呼语石沉大海** —— HR 一天收几百条「您好，我对贵司岗位很感兴趣」。

对应三道处理：规则筛掉明显不合适的 → AI 读 JD 判外包/销售 → 剩下的让模型结合简历写。

## 快速开始

```bash
uv sync
uv run patchright install chromium

cp .env.example .env && vi .env        # 填模型凭据
cp config.yaml config.local.yaml       # 改搜索词、筛选规则（有它就优先用它）
cp ~/你的简历.md resume/                # resume/ 整个目录已 gitignore

uv run boss chrome                     # 启动带调试端口的 Chrome，在里面**手动**登录 BOSS
uv run boss login                      # 确认登录态
uv run boss doctor                     # 选择器自检，确认没被改版打挂
uv run boss run --dry-run -n 5         # 预演 5 个，只生成不发送
uv run boss run -n 3                   # 真发 3 个，去 APP 里核对
uv run boss stats                      # 看统计
```

## 命令

| 命令 | 作用 |
|---|---|
| `boss chrome` | 启动一个开着调试端口的 Chrome，供接管模式使用（`--print-only` 只打印命令） |
| `boss login` | 确认浏览器已登录。接管模式只做确认，自启模式才走扫码 |
| `boss doctor` | 逐条验证 `selectors.yaml` 能否命中真实元素，输出 ✅/⚠/❌ |
| `boss dump [URL]` | 存一份页面 HTML + 全页截图到 `data/logs/`，用于校准选择器 |
| `boss run --dry-run` | 全流程但不发送，打印将要发的招呼语 |
| `boss run -n N` | 真发，最多处理 N 个岗位 |
| `boss run --default-greeting` | 不调模型，只点「立即沟通」，用你在 BOSS 里设好的招呼语 |
| `boss run --allow-fallback` | 模型不可用时也继续跑，全部改用固定模板招呼语 |
| `boss stats --days 7` | 发送统计、各规则拦截量、最近 10 条招呼语 |

## 技术实现

想知道页面数据怎么拿、「立即沟通」按钮怎么找到并点下去、发送成功怎么确认的，
看 **[docs/技术实现.md](docs/技术实现.md)**——薪资的字体密文、旁听接口而不是构造请求、
选择器候选列表、以及那个「消息发出去了却判成失败」的坑，都在里面。

## 流水线

```
搜索接口取列表
   ↓
列表页初筛（只用卡片字段，免费，尽量别进详情页）
   dedup → job_source → rnd_only → topic → keyword → salary → city → education → company_size
   ↓
取 JD（进详情页）
   ↓
详情页复筛  keyword（JD 黑名单）
   ↓
AI 判定  外包 / 销售 → 跳过
   ↓
生成招呼语（LLM 读 JD + 简历）→ 三道校验
   ↓
发送 → 确认 → 入库去重
```

顺序是有讲究的：**免费的规则排前面，花钱的 AI 判定排后面**。一个岗位被 `salary`
刷掉就不必再问模型，跑一轮能省下大半调用。

## 筛选规则

全在 `config.yaml`，每条都能单独 `enabled: false` 关掉。

| 规则 | 作用 | 说明 |
|---|---|---|
| `dedup` | 已打过招呼的不再重复 | 常开，只认 `status='sent'` |
| `job_source` | 挡猎头代招、应届实习 | 见下 |
| `rnd_only` | 只要研发岗 | 岗位名命中产品经理/售前/销售/测试等即拒 |
| `topic` | 方向白名单 | golang / python / nodejs / AI |
| `keyword` | 黑白名单 | 主要用来拦外包，匹配字段含 JD |
| `salary` | 薪资下限 | 用岗位薪资**上限**比较 |
| `city` / `education` / `company_size` | 城市 / 学历 / 公司规模 | |

### 猎头岗：接口里有，DOM 上没有

猎头代招岗跟公司自招混在同一批搜索结果里，标题上完全看不出来。
判据是搜索接口返回的 `proxyJob` / `goldHunter` / `proxyType` 字段
——也就是卡片左上角那个「猎头」角标。实测搜 Golang 一页 15 个里有 7 个是猎头代招。

### 为什么 `topic` 白名单拦不住非研发岗

「AI产品经理」「大模型解决方案专家」这类岗位的 JD 里，AI、Python 堆得比真研发岗还满，
方向白名单一定会放行。所以单独有一条 `rnd_only` 只匹配**岗位名**——
不匹配 JD，因为 JD 里写「配合产品经理」是家常便饭，拿它匹配会误杀一片。

### 词表别配得太宽

拦外包时踩过的坑，现在都有单测盯着：

- `用工` 会卡在「熟练运**用工**作窃取等机制优化调度效率」
- `入驻` 会卡在「完整了解 ISV 应用**入驻**、发布、企业授权全链路」

改用 `人才外包`、`人力外包`、`外包事业`、`常驻客户` 这类复合词，不会跨词边界误伤。

### 英文词按独立单词匹配

`go` 不会被 MongoDB / Django / Google 误伤，`ai` 不会被 chain / training / domain 误伤。
中文词直接包含匹配——中文没有词边界，而且「大模型」这类词本身不会嵌在别的词里。

## AI 判定外包 / 销售

规则黑名单只能匹字面词，而外包岗的写法千变万化：「入驻合作伙伴团队」
「为客户提供驻场技术支持」——一个关键词都不命中。这一层把 JD 丢给模型做二分类：

```yaml
ai_screen:
  enabled: true
  provider: ""          # 留空跟 greeting 走
  model: ""             # 留空跟 greeting 走；判定是轻任务，建议单独指个快模型
  skip: ["OUTSOURCE", "SALES"]
  max_consecutive_failures: 5
```

模型只回一个词（`OUTSOURCE` / `SALES` / `OK`），token 用量很小。JD 截断到 1500 字
——判定线索基本都在开头的公司介绍和职责里。

几个刻意的设计：

- **判定失败放行，但计数**。网关抖一下不该让岗位白白丢掉；
  但连续失败到阈值就停整轮——这层不通等于没开，继续跑会把外包岗一起发出去。
- **先看哪个标签先出现**。模型偶尔会写「OK，这不是 OUTSOURCE 岗位」，
  按出现位置取第一个，避免被后半句带偏。
- **没有 JD 就不判**，也不算模型出错。

## 招呼语

简历作为固定前缀走 prompt caching，批量跑时省下大部分输入成本。

生成后三道校验，任一不过就重试一次，仍失败降级到 `fallback_template`：

- 长度在 `[min_chars, max_chars]` 区间
- **不含手机号/邮箱/微信** —— 简历里就有手机号和邮箱，模型很容易顺手抄进去，
  而 BOSS 会屏蔽含联系方式的首条消息
- 没有整段照抄 JD

超长是唯一「留一手」的失败：重试仍超长但在 1.15 倍以内时，宁可发一条超一点的
针对性招呼语，也不发通用模板。

### 让模型少写点

中文模型对字数的自我控制很差。实测某模型在 200 字上限下连续输出 225 / 300 / 339 字，
每个岗位都降级成模板。有效的做法是**给句子数上限**（「最多三句话」）——
模型跟踪句子数比跟踪字数准得多，配合「这是上限不是目标值」和在 user prompt 里重申，
输出降到 209 / 155 / 133。

### 不想让模型写

`--default-greeting` 完全不碰模型：不建客户端、不探活、不生成，`.env` 里没有凭据也照跑。
点「立即沟通」后由 BOSS 发你在【消息通知-设置打招呼语】里设好的那条。

代价是招呼语对任何岗位都成立，回复率通常明显低于针对性的那条。

## 登录：接管你自己的 Chrome

BOSS 的反自动化会盯着浏览器本身——Playwright 自带的 Chromium 打开登录页，
**两秒内整页刷成空白**，二维码根本不渲染。所以默认走「接管」：浏览器由你自己启动、
登录也由你自己手点，本工具只是通过 CDP 连上去操作已登录的页面。
实测 `navigator.webdriver` 为 `false`，没有任何 `--enable-automation` 痕迹。

```bash
uv run boss chrome     # 等价于下面这条命令，只是省得手敲
```

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --remote-debugging-port=9222 \
  --user-data-dir="<项目>/data/chrome-profile"
```

要点：

- **必须是独立的 `--user-data-dir`。** Chrome 136 起不允许对默认用户目录开调试端口，
  所以这是个专用浏览器，第一次打开是全新的——在里面手动登录一次 BOSS 即可。
- 每次要跑之前，这个 Chrome 得开着。
- 工具退出时**只断开连接，不关你的窗口**；也不会抢占你正在看的标签页。

## 账号安全

自动化操作违反 BOSS 用户协议。**实测记录：一小时内发 42 条，账号被强制登出。**
注意那次并没有触发「今天聊天过多了」的次数上限——是**频率**被风控盯上了，不是总量。

所以真正的约束是**每小时发多少**，不是每天发多少。默认值按此配置：

| 项 | 默认值 |
|---|---|
| 每日上限 | 50 条 |
| **两次发送间隔** | **10–25 秒，另有 15% 概率再乘 1.8–3 倍**（模拟真人分神） |
| 单步操作间隔 | 2–5 秒高斯随机，不是固定 sleep |
| 每发 8–12 条 | 长休息 1.5–3.5 分钟 |

撞上验证码或被登出，**第一个该往回调的是 `send_delay`，不是 `daily_limit`**。
想多发就分几段跑、中间隔开几小时，别把 50 条压在一小时里。

其他保护：

- 页面出现「操作过于频繁」「今日沟通次数已达上限」等文案 → 立即熔断退出
- 连续 3 次发送失败 → 熔断（多半已经被限了）
- `headless: false` 是刻意的：headless 更容易被识别，而且你能盯着它跑

## 配置

**`config.yaml`** —— 搜索词、城市、筛选规则、AI 判定、限速、简历路径。

**存在 `config.local.yaml` 就优先加载它**，没有才回落到 `config.yaml`。
所以自己的配置写进 `config.local.yaml`（已 gitignore），仓库里那份当模板——
`git pull` 不会跟你的本地改动打架。跑起来时会打一行 `配置：config.local.yaml`
告诉你用的是哪份，免得改了半天没生效。

**`resume/`** —— 放你自己的简历，整个目录已 gitignore，只有说明文件进仓库。
简历里通常有手机号和邮箱，不该提交。

**`selectors.yaml`** —— 所有 DOM 选择器。BOSS 前端改版频繁，这是这类工具最主要的
失效来源，所以集中放这里，改版时不用动代码。每个字段是**候选列表**，
按顺序尝试第一个命中的；`boss doctor` 会告诉你哪些失效了、哪条实际生效。

### 模型凭据

`.env`（见 `.env.example`），按 provider 二选一。`provider: openai` 不代表用 OpenAI 的模型
——任何 OpenAI 兼容网关都走这档，具体能用哪些模型取决于 `OPENAI_BASE_URL` 指向哪。

配兼容网关踩过的三个坑，都不会给出像样的报错：

- **`OPENAI_BASE_URL` 末尾的 `/v1` 不能省。** 省了之后请求打到网关的网页端，
  拿回一坨 HTML，SDK 报的是 `'str' object has no attribute 'choices'`
  这种跟配置毫无关系的解析错误。**这个坑踩了两次，两个不同的网关。**
- **模型名以网关认的为准**，不以域名为准。先
  `curl -H "Authorization: Bearer $KEY" <网关>/v1/models` 看它到底认哪些名字。
- **代理设置跟着网关走。** 有的网关是国内直连、挂代理就超时（要加进 `NO_PROXY`）；
  有的反过来，必须走代理、直连被 `Connection reset by peer` 掐断。换网关必须重新确认这一条。

另外：同一家的凭据变量是**一组**的。`.env` 只要声明了某组里的任意一个，
同组里没声明的就会从继承的 shell 环境里清掉——否则 `.env` 配了网关地址、
shell 里恰好有个 key，SDK 会优先拿那个 key 去打你的网关，认证失败而报错看上去
跟配置完全无关。

### 推理模型未必跑得动

同一个网关上快模型一次生成 6–8 秒，而某推理模型带上整份简历的 prompt 直接
Cloudflare 504。慢模型在批量跑里会把整轮拖死，选之前先单测一把。

## 数据

全在 `data/`（已 gitignore）：`chrome-profile/` 接管模式那个 Chrome 的用户目录
（含登录态）、`boss.db` 记录、`logs/` 失败截图与 HTML dump。

`boss.db` 四张表：`jobs`（岗位快照 + JD）、`greetings`（招呼语与结果）、
`rejections`（拦截原因）、`runs`（每轮汇总）。

去重只认 `status='sent'` —— 预演和发送失败的岗位下次还会重试。
`rejections` 表配合 `boss stats` 能看出每条规则拦了多少，用来调参。

## 改版失效了怎么办

1. `uv run boss doctor` 看哪些字段 ❌
2. `uv run boss dump` 存一份真实 HTML
3. 在 HTML 里找到对应元素的新 class，加进 `selectors.yaml` 对应字段的候选列表**首位**
4. 再跑一次 `doctor` 确认变 ✅

## 一个值得记下的坑

早期版本把「点完立即沟通后找聊天气泡」当作发送成功的判据，结果每次都判失败、
攒够三次触发熔断——而实际上**消息全都发出去了**。

BOSS 点「立即沟通」的真实行为是：当场把你设好的招呼语发出去，弹一个
「已向BOSS发送消息」确认框，页面**不会**出现聊天面板。找气泡永远等不到。

教训：发送确认要认平台真正给出的信号。失败截图存在 `data/logs/` 里就是为了这种时候
——一眼就能看出是选择器失效、被风控了，还是压根判错了。
